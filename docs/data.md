# Data

## Run directories

```
benchmark-data/
  00001/
    sightglass.csv.gz
    metadata.toml
  00002/
  ...
```

* `NNNNN` is five-digit, zero-padded, and starts at `00001`. The next number is
  one more than the largest existing directory.
* A run directory is written once and never edited. Corrections are new runs
  or entries in `benchmark-data/excluded.toml`.
* Only successful runs are committed. A run with some failed benchmarks is
  still committed with the benchmarks that succeeded; the failures are listed in
  metadata.

## `sightglass.csv.gz`

Gzipped, unmodified `sightglass-cli benchmark --raw --output-format csv`
output, merged across all per-benchmark invocations:

```
arch,engine,engine_flags,wasm,process,iteration,phase,event,count
x86_64,wasmtime,--target x86_64-unknown-linux-gnu ...,spidermonkey/spidermonkey-json.wasm,0,0,Compilation,virtual-cycles,123456
```

`awfy run` and `awfy record` fix three columns so they are stable across runs:

* `engine` is always `wasmtime` (via `--name`), not a temp path.
* `wasm` is relative to `sightglass/benchmarks/`, not absolute. (`awfy run`
  runs `sightglass-cli` from that directory with relative paths.)
* `process` is the process index, `0` to `processes - 1`, not the OS pid,
  which is noise.

Rows are sorted by `wasm`, `process`, `iteration`, `phase`, `event`, and the
gzip header has no file name or mtime, so the file is reproducible.

`event` is each callgrind counter plus `virtual-cycles`.

## `metadata.toml`

```toml
schema = 1

started = 2026-10-10T03:17:00Z
finished = 2026-10-10T04:21:12Z

[wasmtime]
commit = "0123456789abcdef0123456789abcdef01234567"
# Committer date, so the UI can plot by commit time and not run time.
commit-date = 2026-10-09T22:41:05Z

[sightglass]
commit = "e38856287c8871228d7ff843e29028c381a71dd7"
suite = "benchmarks/default.suite"

[are-we-fast-yet]
commit = "fedcba9876543210fedcba9876543210fedcba98"
workflow-run = "https://github.com/bytecodealliance/are-we-fast-yet/actions/runs/123"

[environment]
valgrind = "valgrind-3.22.0"
rustc = "rustc 1.90.0 (1159e78c4 2025-09-14)"
uname = "Linux runnervm... 6.11.0-1018-azure #18~24.04.1-Ubuntu SMP ... x86_64 GNU/Linux"
cpu = "AMD EPYC 7763 64-Core Processor"

[config]
processes = 3
engine-flags = "--target x86_64-unknown-linux-gnu -Ccranelift-has-sse3 ..."

[failures]
# Benchmarks that failed and have no rows in the CSV, with a short reason.
# "foo/benchmark.wasm" = "exit status 1"
```

Required by the project brief: start time, Wasmtime commit, Sightglass commit,
Valgrind version, `uname -a`. The rest:

* `wasmtime.commit-date` is the x axis of the trend plots.
* `are-we-fast-yet.commit` recovers the workflow, toolchain, and config used.
* `rustc` and `cpu` are cheap to record and help diagnose unexpected jumps.
* `schema` lets readers reject or migrate old metadata.

## Environment fingerprint

`awfy` derives a fingerprint from `sightglass.commit`, `valgrind`, `rustc`, and
`config`: things we change deliberately. Host details (`uname`, `cpu`) are
excluded because the runner's CPU changes often between runs. When two
consecutive runs differ in fingerprint:

* The UI draws a vertical marker between them, labeled with what changed.
* Regression detection skips that pair and reports why in the job summary.

## `benchmark-data/excluded.toml`

Hand-maintained list of runs to ignore, e.g. known-bad data:

```toml
[[excluded]]
run = 42
reason = "Valgrind upgrade mid-run; see #17"
```

Excluded runs are hidden from the UI and never used as a regression baseline.

## Derived data

Generated by `awfy site` at deploy time, never committed. See [site.md](site.md).
